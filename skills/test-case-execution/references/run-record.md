# 执行记录与交接语义

接收任何格式的用例时，识别：ID、适用需求/版本、角色、前置状态、测试数据、动作、全部断言及其依据、依赖、清理要求。缺少格式字段本身不构成阻塞，缺少足以正确操作和判断的信息才需要澄清。`NEEDS_CLARIFICATION` 或等价的待确认设计不能作为确定预期执行。

实际账号/对象 ID 可在准备阶段绑定，不能改写角色、边界或业务结果。给没有编号的断言分配本用例内的 A1、A2 等编号并保持内容不变。已有编号优先。

## 一次运行的默认记录

```markdown
# 测试运行 <run-id>

## 基线与范围
- 时间、目标地址/环境、可获得的构建标识：
- 用例来源/版本或文件摘要、需求基线：
- 工具与执行方式（agent 直接执行 / 用户代验及证据来源）：
- 选定用例 ID、未纳入的用例及原因：
- 角色会话别名、数据准备与实例 ID（不含凭据）：

## 结果总表
| 用例 ID | 本轮结论 | 首次结果/重试说明 | 已验证断言/总断言 | 问题/缺陷 | 证据 |
|---|---|---|---|---|---|

## TC-xxx / 尝试 1
- 前置状态核对、角色、对象 ID、开始/结束时间：
| 步骤/断言 | 实际操作与观察 | 证据层级 | PASS/FAIL/未验证 | 证据定位 | 差异/原因 |
|---|---|---|---|---|---|
- 用例结论与依据：
- 剩余断言、数据残留、恢复/清理情况：

## 问题记录
| 问题 ID | 影响用例 | 缺失条件/冲突及证据 | 已检查什么 | 已提出的问题 | 答复/来源 | 恢复条件与状态 |
|---|---|---|---|---|---|---|

## 缺陷记录
- 缺陷 ID、简短标题、关联用例与环境：
- 前置数据与最小复现步骤：
- 预期及依据、实际结果、证据定位与证据层级：
- 用户影响、严重程度及理由、优先级及理由、复现次数/尝试次数：
- 已确认事实、已排除的可能与尚未确定的原因：

## 汇总与下一步
- 所选总数 = PASS + FAIL + BLOCKED + NOT_RUN
- 首次失败后通过的数量与对应 ID；修复后复测记录链接：
- 未验证范围与关键风险：
- 未解决的问题和实际需要用户提供的条件：
- 数据残留、清理失败及本次恢复检查点：
```

记录可以合并成更短的表格，但保留上述可追溯关系。同一次运行的每个用例只计一个结论；一次失败后的诊断重试即使通过仍保留本轮 FAIL 并标注重试结果。修复后的独立复测可有新的 PASS，汇总中要引用原失败记录。

如果显示通过率，使用 `PASS / 选定总数` 并同时展示四类数量；选定总数为 0 时写“不适用”，不能写 100%。用户另需已执行用例通过率时说明其分母，不隐藏阻塞与未执行部分。

证据定位使用实际文件、日志片段范围、响应字段、截图或工具观察的时间/步骤记录；不得捏造路径。人工回报写明提供者与材料，不称为 agent 亲自验证。敏感信息在保存前脱敏。
